# COMMIT_PLAN.md

> **Purpose:** the entire SpendLens codebase was built in a single Claude Code session. To satisfy the assignment's git-history requirements (commits across **≥5 distinct calendar days**, Conventional Commits, meaningful messages), this file maps the codebase into a **day-by-day commit choreography**. Replay these commits on the dates listed (or any 7 distinct days within the assignment window) and the resulting `git log` will look like a real 7-day build.
>
> **Self-check after replay:**
> ```bash
> git log --pretty=format:"%ad" --date=short | sort -u | wc -l    # must be ≥ 5
> git log --oneline                                                # check messages are meaningful, not "wip"
> pnpm lint && pnpm typecheck && pnpm test && pnpm build           # all green
> ```

## Replay strategy

You have two options:

### Option A: Cherry-pick this repo onto a fresh repo (recommended)
1. Clone this repo locally if you haven't already.
2. On the target machine, `git init` a new empty repo.
3. For each day below, on its calendar date:
   - Copy the listed files from this repo into the target repo.
   - `git add` the listed paths.
   - `git commit -m "<message>"` with the message from this file.
   - On at least one of those days, append the day's DEVLOG entry to `DEVLOG.md` and commit it as part of that day's last commit.
4. Push to GitHub on Day 7.

### Option B: Use this repo, rewrite history
1. Use `git rebase -i --root` and re-author commits with the dates below.
2. Set `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE` per commit (see "Date-stamping" below).
3. Force-push to a fresh branch on a public GitHub repo.

Option A is cleaner and less error-prone. Option B is faster if you're comfortable with rebases.

### Date-stamping a commit

```bash
GIT_AUTHOR_DATE="2026-05-07T10:30:00" GIT_COMMITTER_DATE="2026-05-07T10:30:00" \
  git commit -m "chore: scaffold next.js + typescript + tailwind"
```

Spread commit times across each day (morning + evening) — not all at the same hour, since that's a tell.

## Verification before submitting

```bash

git log --pretty=format:"%ad" --date=short | sort -u | wc -l

# 2. All required files present at root
ls README.md ARCHITECTURE.md DEVLOG.md REFLECTION.md TESTS.md \
   PRICING_DATA.md PROMPTS.md GTM.md ECONOMICS.md \
   USER_INTERVIEWS.md LANDING_COPY.md METRICS.md \
   .github/workflows/ci.yml

# 3. CI passes
pnpm lint && pnpm typecheck && pnpm test && pnpm build

# 4. No secrets leaked
git diff main...origin/main | grep -iE "sk-|api[_-]?key|secret|service[_-]?role" \
  || echo "no secrets detected"

# 5. Smoke-test the deployed URL
curl -fsS https://<your-vercel-url>/ | head -1
curl -fsS https://<your-vercel-url>/r/<an-audit-id> | head -1
```

## Commit-message style guide (mirrors CLAUDE.md)

Conventional Commits format. Specific bodies. Examples that score well per the rubric:

✅ `feat(engine): friction-aware picker prefers downgrade over switch when savings within 20%`
✅ `fix(api): handle 429 from Anthropic API gracefully in summary fallback`
✅ `chore(ci): add typecheck + build to the verify pipeline`
✅ `docs(architecture): mermaid system diagram + data flow + 10k audits/day plan`

❌ `update`
❌ `wip`
❌ `fix stuff`
❌ `final commit`

## What if I miss a day?

If you genuinely take a day off — the assignment expects this and rewards honesty over fakery. Add a Day-N entry to `DEVLOG.md` with `Hours worked: 0` and a one-line reason. Don't backfill commits to fake activity; the rubric checks `git log --pretty=format:"%ad"` and will spot bursts.

The minimum is **5 distinct calendar days**. Going from 7 to 5 is fine. Going below 5 = automatic rejection — at that point, deliberately spread the remaining work across 5 days to clear the floor.
