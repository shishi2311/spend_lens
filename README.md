# SpendLens — A second opinion on your AI bill

A free web app that gives startup founders and engineering managers a defensible audit of their AI tool spend (Cursor, Claude, ChatGPT, Copilot, Anthropic API, OpenAI API, Gemini, Windsurf). Built as Round 1 of the Credex Web Dev Intern application — but designed to be something Credex could plausibly launch on Product Hunt next month.

## What it does

1. A cold visitor lands on `/` and tells SpendLens which AI tools they pay for, plan, monthly spend, seats, team size, and primary use case. Form state persists across reloads.
2. The deterministic audit engine evaluates each tool against four rules (right-plan, cheaper-same-vendor, alternative-tool, retail-vs-credits) and surfaces the highest-savings recommendation per tool — with a friction tiebreaker so a finance person doesn't get told to migrate IDEs to save $20/seat when a downgrade would do.
3. A ~100-word personalized summary is generated by `claude-haiku-4-5` (with a templated fallback on any API failure).
4. Results render at a unique public URL (`/r/[id]`) with proper Open Graph + Twitter card previews and a dynamic OG image showing the savings number — designed to be screenshotted and shared.
5. Email is captured *after* value is shown, never before. High-savings (>$500/mo) audits surface the Credex consultation CTA prominently. Low/optimal audits are honest ("you're spending well") and capture leads with a "notify me" CTA.
6. Bonus: PDF export of the full report at `/api/pdf/[id]`.

## Quick start

### Prerequisites
- Node 20+ and pnpm 9 (`corepack enable && corepack prepare pnpm@9 --activate` if you don't have it).
- A Supabase project (free tier works). Run `supabase/schema.sql` in the SQL editor.
- An Anthropic API key (optional in dev — falls back to templated summary).
- A Resend account + verified sender domain (optional in dev).
- An Upstash Redis (optional in dev — limiter is a no-op without it; warns in production).

### Install + run locally
```bash
pnpm install
cp .env.example .env.local   # fill values
pnpm dev                     # http://localhost:3000
```

### Verify before committing
```bash
pnpm lint        # ESLint (Next + TS)
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest run — must show 14+ passing
pnpm build       # production build smoke
```

### Deploy
- Vercel (recommended): import the repo, set the env vars from `.env.example` in the Vercel dashboard, deploy. SSR routes work out of the box.
- Cloudflare/Netlify: should also work — the app uses `runtime = "nodejs"` for routes that need server-side AI/PDF rendering.

### Database setup (one-time)
1. Create a Supabase project.
2. Open the SQL editor → paste the contents of [`supabase/schema.sql`](supabase/schema.sql) → run.
3. Confirm Row Level Security is enabled on both tables (the migration sets this).
4. Copy the project URL + anon key + service role key into `.env.local` / Vercel env.

## Decisions

Five of the trade-offs that shaped the build:

1. **Next.js 15 (App Router) over plain React + Vite.** SSR is non-negotiable for the share-URL viral loop — without it, Open Graph previews don't render, and the result page is the artifact that gets screenshotted. App Router also gives me file-co-located dynamic OG images via `next/og` without a separate service.

2. **Hardcoded audit rules, not LLM-as-judge.** The assignment is explicit: "knowing when *not* to use AI is part of the test." A finance person needs to read the per-tool reason and agree — that's only possible with deterministic rules whose numbers trace to vendor URLs. AI gets exactly one job: the ~100-word personalized summary, where small per-user variation is the desired behavior.

3. **Friction-aware recommendation picking.** Multiple rules can fire on the same tool (e.g., for Cursor Business at 2 seats, both "downgrade to Pro" and "switch to Windsurf" save $40–$50/mo). The naive max-savings pick recommends an IDE migration to save $10. The engine instead prefers the lower-friction recommendation when savings are within 20% — the same call a finance person would make.

4. **Email after value, no captcha.** Captchas before the audit kill the funnel; the threat model (free public tool, low-stakes) doesn't justify the friction. Defenses: IP rate limit (Upstash sliding window, 5/10min) + honeypot field + server-only Supabase service-role inserts. RLS means anon clients can read audits but never `leads`.

5. **Templated fallback on every external dep.** Anthropic, Resend, and Upstash are all optional at runtime — the app degrades gracefully with explicit warns, never throws. This makes local dev frictionless (no need to register five services to see the audit work) and protects the live deploy from any one provider's outage taking down the audit flow.
